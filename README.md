# MerAlarm_forTelegram

##Thanks for Claude
이 프로젝트는 클로드 코드의 도움을 받아 제작되었습니다.

메루카리(jp.mercari.com)에서 키워드로 신착 상품과 가격 인하를 감시해 텔레그램으로 알린다.

기획 문서: [Notion — 메루카리 키워드 알리미](https://app.notion.com/p/3afa95c6fea98062b2d2c075a335cb36)

## 준비

```bash
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

1. 텔레그램 **@BotFather** 에서 `/newbot` 으로 봇을 만들고 토큰을 받는다.
2. 만든 봇과 대화를 열고 아무 메시지나 보낸다. (봇이 먼저 말을 걸 수 없는 구조라 필수)
3. `.env.example` 을 `.env` 로 복사하고 `TELEGRAM_BOT_TOKEN` 을 채운다.
4. 아래를 실행하면 `TELEGRAM_CHAT_ID` 를 찾아준다.

```bash
.venv\Scripts\python.exe telegram_check.py
```

## 실행

```bash
.venv\Scripts\python.exe -m meralarm
```

### 끄는 방법

실행하면 **작업 표시줄 트레이에 종 모양 아이콘**이 뜬다. 우클릭하면 이렇게 나온다.

```
🔍 감시 중 · 키워드 3개
─────────────────────
   일시정지          ← 체크하면 요청을 멈춘다 (프로그램은 살아 있음)
   로그 열기
─────────────────────
   종료
```

아이콘 색으로 상태를 알 수 있다. **초록이면 감시 중, 주황이면 일시정지.**

트레이가 안 보이면 다른 방법도 있다.

| 상황 | 끄는 법 |
|---|---|
| 콘솔에서 직접 실행했을 때 | `Ctrl+C` |
| 작업 스케줄러로 등록했을 때 | `Stop-ScheduledTask -TaskName MerAlarm` |
| 리눅스 systemd | `sudo systemctl stop meralarm` |

어느 방법이든 **큐에 남은 알림을 최대 15초까지 마저 보내고** 정리한 뒤 끝난다.

> 일시정지는 재개할 때 밀린 요청이 한꺼번에 몰리지 않도록 다음 실행 시각을 계속
> 뒤로 민다. 몇 시간을 멈춰뒀다 켜도 폭주하지 않는다.

로그인할 때마다 자동으로 띄우려면:

```bash
powershell -ExecutionPolicy Bypass -File scripts\register_task.ps1
```

**최초 실행 시 첫 회차는 알림을 보내지 않는다.** 기존 매물을 그대로 적재하고 다음
회차부터 알린다. 키워드를 나중에 추가했을 때도 그 키워드에 대해서만 같은 방식으로
동작하므로, 언제든 키워드를 늘려도 알림이 쏟아지지 않는다.

## 다른 컴퓨터에서 실행하기

### 1. 파일 옮기기

폴더를 통째로 복사하되 **아래 셋은 빼고** 옮긴다.

| 빼야 할 것 | 이유 |
|---|---|
| `.venv/` | 플랫폼에 묶여 있어 옮겨도 안 돌아간다. 새 컴퓨터에서 다시 만든다 |
| `logs/` | 옮길 이유가 없다 |
| `__pycache__/` | 마찬가지 |

`data/seen.db` 는 선택이다. **가져가면** 이미 본 상품을 기억한 채 이어서 감시하고,
**안 가져가면** 첫 회차에 다시 적재만 하고 그다음부터 알린다. 어느 쪽이든 알림이
쏟아지지는 않는다.

`.env` 는 토큰이 들어 있으니 USB나 비공개 경로로 직접 옮긴다. git 을 쓴다면
`.gitignore` 가 이미 제외하고 있으므로 새 컴퓨터에서 손으로 채워야 한다.

### 2. 준비 스크립트 실행

Windows:

```bash
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
```

Linux · macOS · 라즈베리파이:

```bash
bash scripts/setup.sh
```

Python 확인, 가상환경 생성, 의존성 설치, `.env` 준비까지 해주고 다음에 할 일을
알려준다. 이후 안내대로 토큰을 채우고 `telegram_check.py` 를 돌리면 끝이다.

서버로 옮기기 전에는 **그 서버에서 메루카리가 되는지부터** 확인한다. 데이터센터
IP 는 차단될 수 있고, 전부 배포한 뒤에 알면 시간 낭비다.

```bash
./.venv/bin/python scripts/check_access.py
```

IP·통신사와 함께 5회 시도 결과를 보여주고 정상 / 불안정 / 차단됨으로 판정한다.
Oracle Cloud 배포 절차는 [DEPLOY.md](DEPLOY.md) 에 따로 정리했다.

### 3. 계속 켜두기

Windows 는 `scripts\register_task.ps1`, 리눅스는 다음을 쓴다.

```bash
bash scripts/install_service.sh
```

systemd 서비스로 등록되어 부팅할 때마다 뜨고, 죽으면 30초 뒤 되살아난다.

> **두 대에서 동시에 돌리지 말 것.** 같은 봇 토큰을 쓰면 알림이 두 번 온다.
> 옮겼으면 원래 컴퓨터에서는 중지한다.

## 텔레그램 명령어

알림을 받는 그 자리에서 조작할 수 있다. 화면 없는 서버에서는 사실상 유일한 조작 수단이다.

| 명령 | 하는 일 |
|---|---|
| `/status` | 가동 시간, 키워드 수, 요청·알림 통계, 정지 여부 |
| `/list` | 감시 중인 키워드를 번호와 함께 |
| `/add 키워드 [-제외어]` | 키워드 추가. 첫 회차는 조용히 담고 그다음부터 알린다 |
| `/del 번호` | 키워드 삭제. 번호는 `/list` 기준 |
| `/pause` · `/pause 30m` | 잠시 멈춤. 시간을 주면 그 뒤 자동 재개 (`s` `m` `h`, 단위 없으면 분) |
| `/resume` | 다시 시작 |
| `/help` | 도움말 |

### 제외어 붙이기

```
/add 樋口円香 -セット -まとめ
/add 樋口円香 -セット,まとめ
/add ガンプラ MG -ジャンク          키워드에 공백이 있어도 된다
```

**제외어에는 모두 `-` 를 붙여야 한다.** 하나라도 빠지면 그것이 키워드의 일부인지
제외어인지 알 수 없으므로, 추측하지 않고 거절한 뒤 무엇이 잘못됐는지 알려준다.
쉼표 뒤에 띄어쓰는 것(`-セット, まとめ`)도 같은 이유로 거절한다.

잘못된 입력은 **설정 파일에 아무것도 쓰지 않는다.** 절반만 반영되는 일이 없다.

`/add` 와 `/del` 은 `config.yaml` 을 직접 고치고 **재시작 없이 즉시 반영**된다. 이미 돌던
키워드는 실행 리듬과 백오프 상태를 그대로 유지하므로, 키워드 하나 추가한다고 전체
감시가 초기화되지 않는다.

> **`.env` 에 적힌 chat_id 에서 온 명령만 처리한다.** 봇 이름은 검색으로 노출되므로
> 누구나 말을 걸 수 있다. 다른 사람이 보낸 명령은 무시하고 로그에만 남긴다.

설정 파일의 주석은 봇이 고쳐 써도 그대로 남는다(`ruamel.yaml` 왕복 편집).

## 설정

`config.yaml` 을 고친다. 키워드는 문자열 한 줄로 간단히 쓰거나 조건을 붙여 쓴다.

```yaml
keywords:
  - ガンプラ MG                 # 간단형: 조건 없이 전부

  - name: 芹沢あさひ            # 상세형
    query: 芹沢あさひ
    interval_sec: 30           # 이 키워드만 더 자주
    price_min: 1000
    price_max: 50000
    exclude: [セット, まとめ]   # 제목에 있으면 제외
    conditions: [1, 2]         # 새상품·미사용 / 거의 새것만
    shipping_payers: [2]       # 판매자가 배송비 부담하는 것만
```

| 항목 | 값 |
|---|---|
| `conditions` | 1 새상품·미사용 · 2 거의 새것 · 3 눈에 띄는 상처 없음 · 4 약간 상처·오염 · 5 상처·오염 · 6 상태 나쁨 |
| `shipping_payers` | 1 구매자 부담 · 2 판매자 부담 · 3 미정 |

비워두면 그 조건으로는 거르지 않는다.

> **메루카리 Shops 주의** — 검색 결과의 5% 정도는 사업자가 파는 Shops 상품이고,
> 이쪽은 `shipping_payers` 값이 비어 있다. 따라서 `shipping_payers` 를 지정하면
> **Shops 상품이 전부 제외된다.** 알림에는 `🏪 Shops` 표시가 붙는다.

```

├─ ratelimit.py     전역 요청 간격 제어
```

`data/seen.db` 에 본 상품과 가격이, `logs/meralarm.log` 에 실행 기록이 쌓인다.

## 동작 방식에서 알아둘 것

**메루카리 검색의 정렬 순서는 신뢰할 수 없다.** `SORT_CREATED_TIME` 은 최초 출품
시각이 아니라 최근 갱신 시각 기준이라, 3년 전 상품도 가격을 한 번 고치면 상위로
올라오고 그 순서마저 완전한 내림차순이 아니다. 그래서 "마지막 확인 시각 이후만
처리" 같은 최적화는 성립하지 않으며, 매 회차 `item_id` 를 전수 대조한다.

이 성질은 가격 인하 감지에는 유리하다. 가격을 바꾼 상품이 알아서 상위로 올라오므로
따로 조회할 필요가 없다. 다만 재출품이나 설명 수정만으로도 올라오기 때문에 **가격이
실제로 내려갔을 때만** 알린다.

**"처음 본 상품"과 "새로 나온 상품"은 다르다.** 위 성질 때문에 몇 달 전 상품도 갱신
한 번에 상위로 떠올라 우리 눈에 처음 보이게 된다. 실제로 상위 120건 중 15%가 출품
3개월이 지난 것이고 가장 오래된 것은 680일 전이었다. 그래서 두 가지를 둔다.

- `notify.max_age_days` — 출품한 지 그만큼 지난 상품은 후보에서 뺀다 (기본 30일)
- 알림 머리말 — 당일 출품은 `🆕`, 그보다 오래됐으면 `🔁 · N일 전 출품`

`max_age_days` 를 `null` 로 두면 전부 받는다. 대신 몇 년 전 상품이 신규 알림으로
계속 올라온다.

**한 상품이 여러 키워드에 걸려도 알림은 한 번만 간다.** 예를 들어 같은 작품의
캐릭터 이름을 여러 개 감시하면 한 상품에 둘 이상이 함께 나오는 일이 흔하다.
`notified` 표에 이미 알린 상품을 키워드와 무관하게 기록해두고, 두 번째 키워드가
같은 상품을 잡으면 건너뛴다. 가격이 더 내려가면 그때는 다시 알린다.

이걸 제외 키워드로 해결하려 하면 안 된다. 서로의 이름을 각자의 `exclude` 에 넣으면
두 캐릭터가 함께 나온 상품은 양쪽 모두에서 걸러져 **아예 알림이 오지 않는다.**

**필터는 중복 제거보다 먼저 적용한다.** 그래야 상한가 위에 있어서 무시하던 상품이
가격이 내려와 조건 안에 들어오면 새 상품처럼 잡힌다.

**주기를 무리하게 줄이지 말 것.** 한 페이지에 120건이 담기므로 그 안에 신규가 전부
들어오기만 하면 놓치지 않는다. 등록이 빈번한 광범위 키워드도 2분 정도는 여유가 있다.
기본값 60초는 충분히 안전하며, 이보다 짧게 잡으면 차단 위험만 커진다.

**차단이 감지되면 스스로 느려진다.** 429나 403이 오면 주기를 2배씩(최대 15분까지)
늘리고, 연속 성공이 쌓이면 원래 주기로 되돌린다. 연속 실패가 3회를 넘으면 텔레그램으로
알리고, 복구되면 복구됐다고 다시 알린다.

## 현재 범위 (Phase 2)

되는 것 — 다중 키워드, 키워드별 주기와 필터, 스태거링, 지터, 전역 rate limiter,
심야 자동 감속, 429/403 적응형 백오프, 신규 알림, 가격 인하 알림, 묶음 요약,
전송 큐, 에러/복구 알림, 일일 heartbeat, 환율 환산, 로그 로테이션, 자동 시작 등록,
키워드 간 중복 알림 제거, Windows/리눅스 준비 스크립트.

아직 안 되는 것 — Playwright 폴백, ZenMarket 소스(야후옥션·라쿠마 확장), 텔레그램
봇 명령어로 키워드 관리, 통계 리포트. Phase 3 이후.
